## Design specificity verdict

**Grounded, not generic.** The identity is not in the chrome (a stock rail + panel + figures
shell) but in three decisions that exist only because this product is a 1277-key pool with
964 retired rows: dead rows hidden by default with the reason written into the comment
(`keys-ui.ts:404-408`); the count line reporting three numbers — enrolled, dead hidden,
matching (`:474-479`); and plan treated as upstream *evidence* that refuses to render a tier
while a key is held back (`:322-335`). No generic dashboard has that rule.

The generic parts are the KPI strip and the toolbar. The one place the product's own model
breaks is the Plan filter — P0 below.

## What is working

1. **The honest count line** (`keys-ui.ts:474-479`). Three numbers instead of one. It is the
   difference between a filter and a filter the operator can audit.
2. **The list error state that keeps the table header** (`:868-885`). The failure is
   announced inside the table's own footprint with Try again where the data would be.
3. **The bulk-remove confirmation** (`:801-818`). Names the first three keys, states the
   count, the gateway consequence, and why undo is impossible. Correct friction for an
   irreversible action.

## Priority issues

- **[P0] The Plan filter is dead, and it sits next to a destructive bulk action.**
  `keys-ui.ts:131-139` renders `<select id="keyPlan">` with four options. There is no
  `keyPlan` in the `el` map (`:203-232`), no listener, and no `plan` field in `state`
  (`:234`). `visibleKeys()` (`:405-425`) filters on query, status and hideDead only. So Plan
  does nothing. Verified this session from source. Worse, "Select all" (`:937-939`) selects
  every filtered key across all pages, so an operator who sets Plan = "Pay as you go", sees
  the count unchanged, and clicks Select all is now holding the whole ready pool one click
  from Remove selected.
  *Fix:* wire `state.plan` into `visibleKeys()` matching `rowPlan(k).text` and the code, or
  delete the select. Until then, gate `bulkRemove` behind an explicit scope line.
- **[P1] Every list render fetches 25 raw credentials and writes 25 audit rows.**
  `keys-ui.ts:548` calls `fetchRaw(k.id)` per visible row to paint the full key. Each call
  hits `GET /pengatur/keys/:id/raw`, which unconditionally writes `auditRecordNow("keys.raw")`
  (`app.ts:719-724`). With auto-refresh on (`:915`, 15s) that is ~100 audit rows per minute
  of page-view noise, and the audit trail becomes unreadable. It also makes the file's own
  contract at `:11` ("no raw credential ever reaches the browser") false.
  *Fix:* return the full key in `/pengatur/keys/list` once per request and log a single
  `keys.list` row; or make the audit write conditional on an explicit reveal gesture.
- **[P1] A failed key-detail load renders nothing.** `keys-ui.ts:1262-1264` paints the error
  into `el.dailyBars`, inside `#dailyPanel`, which is `hidden` in markup (`:1046`) and only
  unhidden inside `renderDaily()` (`:1167`), which never runs on the error path. Blank page
  after the header. *Fix:* render into a dedicated state block at the top of the console.
- **[P1] "Test all" failure is written into a hidden node.** `keys-ui.ts:769` →
  `GX.say(el.bulkMsg, …)`; `#bulkMsg` lives in `#bulkBar`, `hidden` in markup (`:158`) and
  re-hidden by `paintBulk()` when nothing is selected — the normal case for Test all.
  *Fix:* `GX.notice(…, "err")`.
- **[P1] Probing a row destroys its icon permanently.** `testKey` sets `btn.textContent =
  "Testing"` (`:721`) then `"Test"` (`:735`) on a button whose entire content is
  `PULSE_ICON` (`:599`). After one probe the actions column contains two glyphs and the word
  "Test" in a 172px column holding three controls. *Fix:* `GX.busy`/`GX.idle`.
- **[P1] Mobile: the fixed 65px row height survives the table fold** (`ui.ts:825` vs
  `:1236-1247`). At ≤720px the fold sets `display: block` but never resets height, so each of
  nine cells inherits 65px = ~585px per row instead of ~234px. Not visible above 720px.
- **[P1] Mobile: cell widths keep the desktop column caps** (`ui.ts:716,720,721` vs `:1236`).
  The mobile `width: 100%` loses on specificity to every `[data-l]` rule, so Key/Status/Plan
  stay 250/230/170px inside a full-width card with `justify-content: space-between` still
  spreading label against value — ragged right alignment.
- **[P1] No focus indicator on the command-palette input** (`ui.ts:1124`).
  `.palette-input:focus { outline: none }` with `border: 0` and `background: transparent`,
  overriding the global `:focus-visible` at `:187`. The one control keyboard users land in
  after Ctrl K. WCAG 2.4.7 failure, and the only place in the sheet.
- **[P1] Text inputs lose the ring and keep only a 1px border tint** (`ui.ts:501`). Every
  other control keeps the 2px ring. Measured 4.52:1 light / 4.56:1 dark, so it clears
  1.4.11 but is a consistency defect and a weaker-than-spec indicator.

## Persona red flags

**Alex (power user)**
- Every auto-refresh (15s) rebuilds the whole `<tbody>` (`keys-ui.ts:622-626` + `:506-616`).
  Focus inside a row is destroyed mid-task, every 15 seconds.
- Two "select everything" affordances (`:111` vs `:454`) with different scopes and no visible
  statement of which is which.
- Three icon-only row actions with no keyboard-visible labels; `title` is mouse-only.
- The help dialog promises "Tab — move through the table, row by row" (`ui.ts:1761`), but the
  real tab order is 4-5 stops per row (~110 stops for 25 rows) with no roving tabindex.

**Sam (accessibility-dependent)**
- `th[scope]=0 of 9` and no `<caption>` on the keys table (`tableHead`, `:449-465`). The
  primary surface of the console is announced as an unnamed "table".
- 1 input with no label (measured). The thead checkbox has `aria-label` but its wrapping
  `<label class="pickbox">` is empty (`:451-455`).
- `ui.ts:810-812` — at ≤1180px, Fails and Last used are `display:none`, not visually hidden:
  removed from the accessibility tree, with nothing announcing they were dropped.
- Two `#toasts` nodes exist in the document (`ui.ts:1543` appends `toastMount()`;
  `keys-ui.ts:92` injects `noticeBand()` returning the same id). Duplicate id, duplicate live
  region. `GX.toast` only populates the first.
- The detail page's `Enabled` row (`:1145`) reports state the operator cannot change — no
  control anywhere calls `setEnabled`.

## Minor observations

- `keys-ui.ts:1143` renders the plan **code** on detail ("paid") while the list renders the
  **label** ("Pay as you go"). Same fact, two vocabularies.
- `.defs` is a 3-column grid for 7 items (`ui.ts:704`) — the last row has one item and two
  empty cells.
- `keySize` and `hideDead` are not written to the URL (`:966-970`), while q/status/page are.
- `fetchRaw` caches forever (`:339`); a rotated key keeps its old value until reload.
- Detail page has no Test / Validate / Remove action — all three exist only in the list.
- `admin-ui.ts:349-355` — a failed overview load leaves `#console` hidden: blank page plus a
  toast, no retry affordance.
- `renderKpis` (`:446`) prints `pool.storage` through `GX.stat`, which does `String(value)`
  with no guard — a missing field renders the literal word "undefined" at 27px.
- `tag[data-tone="ok"]` drops to 4.16:1 on a hovered row in light theme (`ui.ts:622, :661`) —
  below 4.5 at 11.5px. Every other tone passes in both themes and both row states.
- The thead select-all checkbox is not `accent-color`ed (`ui.ts:573` only under `td`), so it
  renders in the UA default blue while row checkboxes use `--accent`. Two blues on one table.
- Toast dismiss target is 22×22 (`ui.ts:1061-1062`), under the 24×24 WCAG 2.5.8 minimum;
  corrected on coarse pointers only, so the failure is desktop-mouse specific.
- Control boundaries are 1.66:1 in both themes (`ui.ts:33, :98`) — `--line-2` is the entire
  affordance for `.input`, `.select`, `.textarea` and `.btn`, where 1.4.11 wants 3:1. The
  single highest-leverage token change in the sheet.
- `role="combobox"` with no `aria-activedescendant` and a hardcoded `aria-expanded="true"`
  (`ui.ts:1833-1837, :2438, :2463`). Arrow keys move `aria-selected` while DOM focus stays in
  the input, and the options carry no `id`, so the combobox can never point at the active
  option.
- Dead selection styling: `.table tbody tr[aria-selected="true"]` (`ui.ts:665`) and
  `.check input:indeterminate` (`:547`) have no producer — `grep aria-selected src/keys-ui.ts`
  and `grep indeterminate src/` both return nothing. Two specified visual states are
  unreachable.

## Questions to consider

1. If the raw key is now shown in full in the list, what is the masked form still protecting
   — and why does `/raw` remain a separate, individually audited endpoint?
2. The console hides 964 dead rows to protect the operator from scrolling. What else is being
   hidden rather than decided — and is "Remove selected" the decision that was supposed to
   happen to those 964 keys a long time ago?
3. Every page in this shell answers "what is the state". None answers "what changed since I
   last looked". For an operator who opens this console twice a day, is the 15s auto-refresh
   buying anything, or is it just destroying focus?
