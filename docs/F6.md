# F6 — Durable key material

Raw API keys now survive a cold start. `keys` still holds only the masked
identity (`sha256(raw)[:12]`, masked form, tier, health); the raw value lives in
`key_material`, joined on the same `id`.

## Storage is plaintext, deliberately

`key_material.raw_key` is stored **unencrypted**. Anyone who can read that table
can read every live API key.

The alternative — AES-GCM with a key in `KEY_ENC_SECRET` — was rejected because
the encryption key would sit in the same Vercel environment as `DATABASE_URL`,
so it protects nothing against the realistic threat (environment or database
read access) while adding a new failure class: rotate the secret and every
stored key becomes undecryptable, taking the pool down with it. The console is
single-operator and the database is managed Postgres.

Do not reintroduce crypto here without changing this decision explicitly.

## Contract

- `src/key-material.ts`: `materialEnabled()`, `loadMaterial()`, `saveMaterial()`,
  `deleteMaterial()`. Every write is `sqlLater` (fire and forget, off the request
  path), matching `persistIdentity` in `pool.ts`.
- `hydrate()` order: `GEMINI_API_KEYS` → `key_material` → `keys` identity
  overlay. The `pool.hydrated` log payload carries a `material` count.
- A missing table, an open breaker or a timeout yields an empty material map and
  one `key_material.load_failed` warn line; hydration never throws.
- `addKey()` writes the material row, `removeKey()` deletes it.
- `POST /pengatur/keys` reports `durable: boolean`; when false it also returns a
  warning that the key lives only until the next cold start.

## Method gate

`/pengatur/*` console shells are public for reads only (`GET`, `HEAD`,
`OPTIONS`). `POST`/`DELETE` to a shell path — including `POST /pengatur/keys` —
fall through to the token check: `403` when `ADMIN_TOKEN` is unset, `401` on
mismatch. `/admin/*` and `/models/*` remain 404.
